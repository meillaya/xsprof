# xsprof 0.3.0 audit and remediation

Date: 2026-11-06. Scope: correctness, durability, operator UX, web security,
packaging, and release quality. The profiler remains read-only on the host.

## Evidence collected before changes

- `./tools/zig build check` was green, but the committed real capture
  `fixtures/real/macos-vm-sched.ndjson` had **88 timestamp reversals**
  (41 within one CPU) in 110,284 rows because independent perf rings were
  drained in ring order.
- All **94,152** switch rows had `pid == b` (previous task) while `comm` named
  the next task; all **54** wakeup rows had `pid != a` (waker) while `comm`
  named the woken task. UI rows rendered `comm`/`pid` together.
- All **16,063** page faults had `b=0`; the combined `SW_PAGE_FAULTS` counter
  made major faults invisible.
- `web/main.js` referenced `web_ui_scroll` and `web_ui_pointer_leave`; neither
  was exported from the wasm, so wheel zoom threw and pointer-leave was a
  no-op.
- Live web mode refetched the whole journal every ~300 ms and called
  `App.loadJournalData`, which resets scroll/selection/playhead.
- `record` and `capture` accumulated their whole result in memory; `capture`
  used `extract.extract()` instead of the existing streaming `writeTo`.
- The daemon installed no SIGTERM/SIGINT handler; `systemctl stop` lost the
  buffered segment and left the manifest in `recording`.
- Sidecars were written at every rotation (774 in a documented 10-minute run),
  never pruned, and write failures were ignored.
- Manifest readers did not validate schema, `host_mutation`, or segment paths.
- The live-dir spool could publish partial JSON lines and missed rotation tails.
- `docs/safety/invariants.md` claimed QA gates that did not exist
  (`unsafe_cli_matrix.sh`, `no_host_mutation.sh`, `privacy_scan.sh`).
- There was no top-level LICENSE.
- A plain `zig build` did not install web assets; `demo` failed with 503 on a
  clean checkout, and the Debian packager assumed `zig-out/web` existed.
- Release CI created `.sha256` files but did not upload them and did not run
  the test gate before publishing.
- There was no live `top` view and no one-command root-cause report.

## Remediation

| Area | Change |
|---|---|
| Ordering | `Capture.take()` sorts batches by timestamp/CPU/kind/pid; replay tolerates old skew and reports `metrics.out_of_order`. |
| Loss | One `PERF_RECORD_LOST` marker is journaled; the duplicate daemon/serve markers were removed. |
| Page faults | `SW_PAGE_FAULTS_MIN`/`MAJ` rings; `page_fault.b=1` for major, with a combined-counter fallback. |
| Event identity | Documented `a/b/c/pid/tid/comm`; `subjectPid()`/`actorPid()` used by the UI and filters. |
| Memory | `record` streams through `recordStream`; `capture` streams through `extract.writeTo`. |
| Durability | SIGTERM/SIGINT handler flushes the segment, writes `capture_stop`, and marks the manifest stopped. |
| History | One sidecar per 60 s bucket (configurable), 24 h retention, prune and error accounting, validated sidecars. |
| Input safety | 64 KiB line, 64-deep JSON bound, required `host_mutation=false`, manifest/sidecar schema and path validation. |
| Live web | `web_ui_append_journal` with a bounded store/index; the model is rebuilt without resetting the view. |
| Web security | Fragment token, constant-time compare, CSP/referrer/frame headers, HEAD, journal validation, live fail-closed. |
| Commands | `top`, `why`, `report`, `completions`; quickstart, command help, timestamped defaults, safe output, human doctor. |
| Distribution | MIT LICENSE, version 0.3.0, default web install, Debian web assets, release check gate and checksum upload. |
| Gates | New `unsafe_cli_matrix`, `no_host_mutation`, `privacy_scan`, `web_ui_smoke`, `version_sync`, `live_smoke`. |

## VM verification (Fedora 44 x86_64, podman machine)

- `record --duration 1s`: ~85k–88k events (run-dependent), switches ~85k,
  wakeups ~100, faults minor ~2.6k / major 13, zero loss; one cross-batch
  out-of-order row in ~85k timed rows (per-batch sorting is not a global
  merge).
- `top --duration 1s --json`: canonical metrics, real CPUs/tasks.
- `why --input`: schema `xsprof/why/v1`, wakeup pairs and faults.
- `daemon --duration 3s --history-interval 1s`: manifest stopped, three
  sidecars, `history` schema present.
- SIGTERM: manifest stopped and `capture_stop signal=terminated` present.
- `bpf-gate`: READY with VM marker and `host_mutation=false`.
- `qa/service_smoke.sh`: PASS (6 segments, 334,064 extracted lines).
- `qa/live_smoke.sh`: PASS.
- `qa/retention_bench.sh 20000 2 2G yes`: 1,594,725 events at ~79.6k/s,
  one 60-second history bucket at the 20 s stop, 0 lost events, zero retention
  drops, ~10 MB RSS.

## Residual limits

- A replay of a legacy journal can still contain cross-batch timestamp skew;
  `out_of_order` and `why` surface it instead of hiding it.
- Native live streaming, a full accessibility tree, notarization/tap
  publication, AUR packaging, and a compact raw 10-minute tier remain out of
  scope. BPF stays a VM-marker-gated no-op gate; no host mutation was added.
- The 60-second history cadence changes the old per-segment sidecar profile;
  the 10-minute sidecar numbers in older docs are historical evidence, not a
  re-measurement of the new cadence.
